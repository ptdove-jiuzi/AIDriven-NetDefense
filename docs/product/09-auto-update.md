# 09 · 自动更新

> 状态：**设计已定，尚未实现**。前置条件是仓库公开并产出第一个 Release。

## 1. 怎么用

托盘图标右键 →「检查更新」。有新版时弹一条：版本号、更新说明、包大小。
点「下载并安装」→ 校验 → 提示「重启生效」→ 重启后就是新版。

设置里可以打开「自动检查」（默认开，只检查不下载），也可以关掉，改成手动点。

## 2. 三条底线

1. **不会偷偷装**。下载可以自动，安装必须你点。
2. **装坏了能回去**。新版启动 30 秒内没通过健康检查，自动切回上一版。
3. **你的数据不动**。更新只换程序目录，`data\` 原样保留。

## 3. 从哪更新

从项目的 GitHub Releases 拉。地址写死在程序里，改配置文件也改不掉——
这是故意的：如果更新源能改，等于谁都能给你推一个"新版"。

## 4. 没有代码签名，怎么保证安全

| 手段 | 能证明什么 | 不能证明什么 |
|---|---|---|
| HTTPS + 固定 GitHub 仓库 | 包来自这个仓库 | 仓库账号被盗则失效 |
| SHA256 校验 | 包没被改过 | 谁发的 |
| （可选）minisign 签名 | 确实是发布者签的 | — 本期未配置 |

所以：**哈希只防篡改，不防冒充**。真正的信任根是 GitHub 账号本身。

## 5. 什么情况下会强制

只有一种：发布者在 Release 里标了 `minVersion`（用于安全事件）。
这时启动会弹一个不能跳过的提示，但**仍然要你点**「立即更新」，不会自己装。
