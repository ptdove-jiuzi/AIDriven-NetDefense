# 08 · 模型接入与分级（多 API / 小模型常态 / 大模型应急）

> 本文是产品侧说明。决策依据见 `docs/implementation/adr/ADR-0010-multi-provider-model-routing.md`。
> **当前状态：设计已落文，功能未实现。** 现有版本只有一个固定端点，不能在界面里换。

## 1. 一句话

把「一直用贵模型」换成「平时用小模型盯，出事才叫大模型来」。
默认接 DeepSeek 官方，也可以同时接本地模型和别的兼容 OpenAI 协议的服务。

## 2. 默认值

| 项 | 默认 |
|---|---|
| Provider | `deepseek`，`baseUrl = https://api.deepseek.com/v1` |
| 凭据 | 本地凭据槽（DPAPI/keyring），**不写配置文件、不进日志** |
| 常态模型 | `watch` 级（最便宜的一档，可指向本地模型） |
| 应急模型 | `respond` 级（强模型），**默认不启用**，需要你显式指定 |
| 日预算 | 30k 输入 / 6k 输出（UTC 日），单次分析 12k/2k |

没有配置任何强模型时，系统只跑 watch 级，**不会**偷偷调用贵模型。

## 3. 三个级别怎么选

| 级别 | 你可以填什么 | 它负责什么 | 单次上限 |
|---|---|---|---|
| `watch` | 本地 2B–7B（Ollama/llama.cpp），或最便宜的 API 小模型 | 盯守、归并告警、判低危 | 4k tokens |
| `triage` | 中等模型 | 复核 watch 的结论、写证据摘要 | 8k tokens |
| `respond` | 强模型（如 DeepSeek 旗舰） | 确认攻击、给拦截方案 | 12k tokens |

`watch` 级**不允许**直接产生响应动作 —— 它只能建议，不能动手。

### 3.1 分级可以关（默认开启）

「分级」是一个开关，不是唯一形态。设置里有两项：

| 模式 | 什么时候用 | 代价 | 你会失去什么 |
|---|---|---|---|
| **分级（默认）** | 想省钱、有本地小模型 | 常态便宜，出事才贵 | 小模型漏判时**不会升级**，那次就按小模型结论走 |
| **不分级** | 想稳、不想赌小模型 | 每次分析都走你指定的那个模型，费用明显上升 | 没有"分级递进"这层保护，防御能力完全取决于所选模型 |

要点：

- 关掉分级时，**必须**选一个「主模型」，所有分析都用它；不选不允许保存。
- 关掉分级**不等于**关掉预算：单次 12k/2k、每日 30k/6k、单分析 3 请求仍然生效，用完照样拒绝。
- 切回分级时，之前配的 watch/triage 模型还在，不用重填。
- 每次切换都会记一条审计（时间、谁改的、从什么改成什么），AI 无权改这个开关。

建议：**先用分级跑一周**，看「用量」页里升级了几次、有没有高危被小模型判成低危；
如果发现漏判，再切到不分级，而不是一开始就全量用贵模型。

## 4. 什么时候会升级

必须同时满足，才会从 watch 升到 triage/respond：

1. 检测层判定 `severity >= high`，或命中 critical 规则；
2. watch 已经给出结构化结论（不是把原始日志丢过去）；
3. 同一个告警指纹 5 分钟内没升级过；
4. 这一小时升级次数没超过上限（默认 20）；
5. 目标 provider 今天的预算还有余额。

升级请求里**只带摘要和证据引用**，不带原始事件全文 —— 这是省钱的关键，也是防止把敏感日志整包发出去。

## 5. 省钱的具体四条

1. **平时不叫大模型**：没有高危就不升级。
2. **同指纹不重复问**：15 分钟窗口内合并，命中缓存直接返回。
3. **只发摘要**：升级时发的是 triage 产出的结构化摘要，不是原始日志。
4. **有上限**：单分析 3 次请求、单次 12k/2k、每日 30k/6k，按 provider 还能再设一层上限。

超出预算时**直接拒绝新请求**，不会降级到"用别的模型凑合"，也不会假装成功。

## 6. 大模型挂了会怎样

- 界面显示 `degraded`（降级中），不是静默失败；
- 回落到 `watch` 继续盯守；
- **不会**自动换下一个更强/更贵的 provider 重试（一次分析只允许一次升级）。

## 7. 能接什么、不能接什么

**能接**：

- 任何 OpenAI 兼容的 `/v1/chat/completions` 服务（HTTPS）；
- DeepSeek 官方；
- 本地 Ollama / llama.cpp（`http://127.0.0.1:11434/v1` 这类回环地址，需要显式允许）。

**不能接**：

- `http://` 的公网地址（只允许 HTTPS；回环才允许 http）；
- 带用户名密码的 URL（`https://user:pass@host`）；
- 带查询串或锚点的地址（`?x=1`、`#a`）；
- 会 302 跳到别的主机的地址 —— 我们不跟随重定向；
- 走系统代理的地址 —— 本产品明确忽略 `HTTP(S)_PROXY`。

最多 8 个 provider。超过就不是个人安防工具了。

## 8. 你会看到的用量信息

「用量」页按 provider × 级别聚合：请求数、输入/输出 token、升级次数、最贵的一次分析、今日余额。
每条请求都能追到 `providerId + modelId + tier + fingerprint`，便于核对账单差异。

> 注意：本地预算是**准入上限**，不冒充 provider 的账单上限。真要绝对封顶，还得在 provider 侧设限额。

## 9. 常见问题

**Q：我只填一个 DeepSeek，能用吗？**
能。这就是默认形态，等于现在的行为，只是端点可以在界面里改。

**Q：我有本地 7B，能不能只用它？**
能。把 `watch` 指向本地模型，`respond` 留空，系统就永远不升级，成本为零。

**Q：升级判据能不能我自己改？**
能改阈值（severity 门槛、冷却、小时上限），但「必须带结构化结论」这条不给改 —— 它是省钱和安全的地板。

**Q：为什么不能随便填 URL？**
因为一旦允许任意 URL，就等于允许把凭据和日志发到任意主机。白名单是这条功能的代价，不是限制。
