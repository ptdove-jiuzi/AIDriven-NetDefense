# 测试与验收设计

- 版本：v1.3（随软件设计说明书定稿）
- 文档负责人：PT-dove
- 所有项目当前均为“已设计，未执行”

## 1. 通用门禁

- OS 矩阵：Windows 11 x64、Ubuntu 22.04、Ubuntu 24.04、Debian 12 x86_64；标记 ALL 的用例必须在四个 OS 分别通过。
- 每个用例保存环境、输入清单、步骤、oracle、日志和产物。skip/xfail/flaky/quarantine/not run 均不算通过，重跑不抹除 flaky 历史。
- 测试注入临时数据目录，前后对真实目录做文件快照；任何变化都判失败。
- 变异门禁先运行原始实现并全绿，再独立禁用控制；对应安全测试必须杀死变异体，不能读取同一开关作为唯一 oracle。
- 响应能力按动作×OS 验收；裁剪必须同步移除构建、策略和 IPC/API 端点，直接调用拒绝且零副作用。

## 3. 缺陷与发布判定

- P0：越权、无审批副作用、重大数据破坏。必须修复，不能通过文档或裁剪标记关闭；若裁剪，须证明端点不可达。
- P1：核心守护中断、预算绕过、重大隐私外泄、重复响应。必须修复或按完整能力裁剪。
- P2：有规避的局部问题。仅可由主会话书面接受并公开。
- 四个 OS 的必测证据不齐，不得发布“支持”声明；仅文档完成不更改任何测试状态。
