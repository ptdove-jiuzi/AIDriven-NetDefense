# 国际化（i18n）规范

- 状态：**生效**（2026-11-04 由维护者 PT-dove 定）
- 适用范围：**WebUI 全部界面文案**。桌面壳（托盘/菜单/对话框）与安装器后续复用同一套词条。
- 支持语言：`en`（默认）、`zh-CN`、`ja`、`ko`、`es`、`ru`、`th`

---

## 1. 硬要求

1. **默认英文**。首次启动按系统语言匹配，匹配不到回落 `en`；用户可在设置里改，选择写入本地配置并持久化。
2. 界面里**不允许出现硬编码文案**。任何用户可见字符串都必须来自词条文件。
3. 切换语言**不重启**即时生效（WebUI）；桌面壳的托盘/菜单允许重启后生效，但必须提示。
4. 七种语言必须**同时存在**；缺词条时回落 `en`，并在开发模式下高亮显示缺失项。
5. 构建期校验：CI 里跑一条「词条完整性」检查，任何语言缺 key 即失败。

---

## 2. 文件布局

```
apps/console/i18n/
├─ index.js              # 加载器：detect → load → t()
├─ locales/
│  ├─ en.json            # 基准语言（唯一权威 key 集合）
│  ├─ zh-CN.json
│  ├─ ja.json
│  ├─ ko.json
│  ├─ es.json
│  ├─ ru.json
│  └─ th.json
└─ glossary.md           # 术语对照表（见 §6）
```

`en.json` 是**唯一 key 权威**：其他语言多出的 key 视为错误，缺少的 key 视为未完成。

---

## 3. Key 命名

- 扁平点分：`nav.overview`、`alert.severity.high`、`settings.language.label`
- 只允许小写字母、数字、点、连字符；不允许空格与下划线
- 按「区域.组件.语义」三段，不按句子内容命名（禁止 `clickHereToSave`）
- 同一语义只允许一个 key，禁止 `save` / `btnSave` / `saveButton` 三份

## 4. 值格式

| 规则 | 说明 |
|---|---|
| 占位符 | `{count}`、`{name}`、`{time}`，大括号内只允许标识符 |
| 禁止拼接 | 不允许 `t('a') + t('b')` 拼句子；语序不同的语言会碎 |
| 禁止 HTML | 值里不写标签；需要强调时由组件包裹，不写进词条 |
| 复数 | 用 `Intl.PluralRules`，词条写 `item.count.one` / `item.count.other`；`ru` 有 4 类、`es` 2 类、`ja/ko/th/zh` 1 类 |
| 日期/数字 | 一律 `Intl.DateTimeFormat` / `Intl.NumberFormat`，不手工拼 `YYYY-MM-DD` |
| 长度 | 词条值不超过 120 字符；按钮类不超过 24 字符（`de`/`ru` 会明显变长，按 1.35× 预留） |
| 标点 | 句末标点写进词条；中文用全角，英文/俄文/西班牙文用半角 |

## 5. 不做的事

- 不做机器翻译直出：每个语言至少一次人工过目（可由维护者本人完成），提交信息里注明「reviewed」或「unreviewed」
- 不翻译：产品名 `AIDriven NetDefense` / `网域智防`、协议名、文件名、日志原文、错误码
- 不做 RTL（本期无阿拉伯语/希伯来语）
- 不在词条里写品牌口号或营销语

## 7. 加载与回落

```
detect: localStorage['ui.locale'] → navigator.languages → 'en'
load:   locales/<locale>.json；失败或缺失 → locales/en.json
t(key): locale[key] ?? en[key] ?? '[missing:' + key + ']'
```

- 开发模式（`?i18n=debug`）下，回落命中的词条加黄色下划线，`[missing:]` 加红底
- 生产模式不显示调试标记，但 `[missing:key]` 仍要显示，禁止静默空白

## 8. 语言选择器

- 位置：设置 → 外观 → 语言
- 每个选项显示**该语言的自称**（English / 简体中文 / 日本語 / 한국어 / Español / Русский / ไทย），不显示英文名
- 切换后立即重渲染，不刷新页面
- 桌面壳与安装器读同一份 `ui.locale`，保证「装的时候选中文，打开也是中文」

## 9. CI 校验

```bash
node scripts/i18n-check.mjs
```

检查项：

1. 七种语言文件都存在且能 `JSON.parse`；
2. key 集合与 `en.json` 完全一致（多、少都报错）；
3. 占位符一致（`{count}` 在每种语言里都出现且拼写相同）；
4. 空值、`TODO`、纯英文残留（针对 ja/ko/ru/th 的语言特征检查）报警；
5. 值长度超限报警。

任一失败即 CI 红，不允许「先合并后补翻译」。

## 10. 交付节奏

1. 先落框架：加载器、`data-i18n` 绑定、语言选择器、`en.json`（首批 100–150 条真实词条）
2. 再落 `zh-CN`（作者母语，作为语义校对基准）
3. 再落 `ja / ko / es / ru / th`，每语言单独一次提交，标明 reviewed/unreviewed
4. 最后接 CI 校验与缺失词条报告
